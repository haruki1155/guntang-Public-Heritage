Atomic Design System Manual

A practical reference for the visual language, reusable Vue components, page structures, and accessibility conventions used in this Nuxt project.

1. System overview

This project uses Atomic Design to keep the tourism showcase consistent and maintainable. Small interface primitives are composed into focused controls, then into page-level experiences.

Source of truth: design tokens live in app/assets/css/main.css; component behavior and styles live beside each Vue component.

2. Design principles

Clear and welcoming

Use short descriptions, strong headings, and generous spacing to make destinations easy to scan.

Mobile first

Start with a single-column layout, then enhance it at 40rem, 48rem, and 64rem breakpoints.

Accessible by default

Use semantic landmarks, visible focus states, descriptive image alt text, and a 44px minimum interactive target.

3. Design tokens

Color palette

--color-primary #176B55
--color-primary-dark #0F4F3F
--color-accent #E6B84A
--color-surface #F5F7F6

Spacing and shape

Spacing is based on a 0.5rem scale from --space-1 through --space-6. Use --radius-sm for controls, --radius-md for cards, and --radius-lg for larger feature treatments.

Typography

The system uses Arial, Helvetica, sans-serif. Eyebrows are uppercase and bold; page titles use a responsive clamp() size; muted body copy uses --color-muted.

5. Component guidance

BaseTypography

Use for paragraph copy and apply tone="muted" for supporting text. Set as when the semantic element needs to change.

<BaseTypography tone="muted">
  Supporting destination copy.
</BaseTypography>

BaseButton

Use for actions inside forms or interfaces that need a button. Provide type explicitly when the context is submit or reset.

<BaseButton type="submit">
  Search
</BaseButton>

HeritageCard

Displays a destination image, location, title, summary, and route link. It receives destination data through props and should not own data-fetching logic.

HeritageGrid

Receives a typed Destination[], renders cards, and handles responsive one-, two-, and three-column arrangements with container queries.

6. Data and page composition

All five destinations are defined in data/destinations.ts. Each item has a stable slug, title, location, summary, detail copy, image, and accessible image alt text.

destinations → HeritageGrid → HeritageCard → /destinations/[slug]
                         ↘ shared tokens and primitives

The dynamic destination page looks up the slug, renders a shared detail layout, sets page metadata, and returns a 404 error for unknown destinations.

7. Accessibility checklist

  • Use one clear h1 per page and logical heading order.
  • Keep navigation inside a labeled nav landmark.
  • Provide meaningful alt text for destination imagery.
  • Preserve :focus-visible styles and keyboard access.
  • Use semantic links for navigation and buttons for actions.
  • Keep interactive controls at least 44px high.

8. Extension rules

When adding a new destination, add one typed object to destinations.ts with a unique slug and image alt text. Reuse the existing card and dynamic detail route before creating a new component. Add a new atom only when the visual or behavior is genuinely reusable across multiple molecules.
